# A 股「资金共识」选股工作流

一套跑在扣子编程（Coze Coding）低代码工作流上的选股流水线：**先看钱去了哪 → 再看板块是否连续 → 再看产业逻辑 → 最后才落到个股和估值**。

不是选股策略库，是一个把「资金共识」拆成可执行步骤的工具。

## 数据流

```
S1-A 取榜单(HTTP)
   │  body
   ▼
S1-B 归一化(代码) ── top20 / filter_str
   │                        │
   │                        ▼
   │                 S1-C 取标签(HTTP)
   │                        │ body
   ▼                        ▼
S1-D 合并去噪(代码) ◄───────┘
   │  raw_payload + trade_date
   ▼
S2-E1 写库(数据库) ──→ raw_daily
   │
   ▼
S2-E2 查库(数据库) ── 近 3 日
   │  outputList
   ▼
S2-E3 聚合连击(代码) ── hits / watchlist
   │                        │
   │                        ▼
   │                 S3-F 共识打分(代码) ── scored / picks
   ▼                        │
  结束 ◄────────────────────┘
```

**关键设计：库里只存原始数据，指标在读取时现算。**
这样阈值随时可调，历史数据自动按新口径重算，不会断层。

## 节点清单

| 节点 | 文件 | 类型 | 输入 | 输出 |
|---|---|---|---|---|
| S1-B 归一化 | `nodes/node_s1b_normalize.py` | 代码 | `body` | `top20` `code_in` `filter_str` `cut` `n` |
| S1-D 合并去噪 | `nodes/node_s1d_merge_tags.py` | 代码 | `stock_list` `tag_body` | `stock_tags` `n_tag_total` `raw_payload` `trade_date` |
| S2-E3 聚合连击 | `nodes/node_s2e3_aggregate.py` | 代码 | `records` | `hits` `watchlist` `trade_date` `days_total` `tot_amt` |
| S3-F 共识打分 | `nodes/node_s3f_score.py` | 代码 | `records` `watchlist` | `scored` `picks` `passed` `strong` |

两个 HTTP 节点（S1-A 取榜单、S1-C 取标签）不需要代码，接口与参数见 [docs/](docs/)。

### 数据表

表 `raw_daily`（一天一行）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `trade_date` | String | `2026-10-28` |
| `payload` | String | 当日 20 只票（含板块标签）的 JSON |

## 如何在扣子里使用

每个 `.py` 文件**就是粘贴进扣子代码节点的完整内容**，文件顶部的注释写了节点名、类型、位置、输入输出。

步骤：

1. 扣子编程 → 新建低代码应用 → 建工作流
2. 按上图的顺序添加节点
3. 代码节点：把文件内容整段粘进去
4. 按文件顶部「输入 / 输出」表，在右侧面板逐个添加参数
5. **绑定变量时必须选到字段，不能选整个节点**

> 绑定错误是这个项目最高频的故障：`body`、`filter`、`records` 都踩过。
> 判断方法：值框里显示字段名（如 `S2-E2.outputList`）= 对；显示节点名 = 错。

## 阈值在哪调

所有可调参数都提到了文件顶部，改的时候 diff 只显示一行。

### `nodes/node_s1d_merge_tags.py`

| 变量 | 说明 |
|---|---|
| `DROP` | 固定黑名单：明确无语义的标签 |
| `PATS` | 正则黑名单：指数成分、资金持仓、规模、地域、行业分级、业绩预告 |

### `nodes/node_s2e3_aggregate.py`

| 变量 | 默认 | 含义 |
|---|---|---|
| `MAX_DAYS` | 3 | 回看天数 |
| `MIN_N` | 2 | 板块至少几只票上榜 |
| `MIN_SHARE` | 3.0 | 占 Top20 成交额比重（%） |
| `MIN_W_EFF` | 1.5 | 有效只数门槛 |
| `DEDUP_JACCARD` | 0.85 | 近义板块归并的重合度 |
| `STRONG_STREAK` | 3 | 强候选的连续天数 |
| `WATCH_STREAK` | 2 | 观察等级的连续天数 |

### `nodes/node_s3f_score.py`

| 变量 | 默认 | 含义 |
|---|---|---|
| `WEIGHTS` | 各 20 | 五个维度的权重（广度/资金/强度/趋势/健康） |
| `GATE_STRONG` | 70 | 强共识门槛 |
| `GATE_WATCH` | 50 | 观察门槛 |
| `MAX_PICK` | 3 | 最终推荐几个板块 |
| `PICK_JACCARD` | 0.5 | 挑选时与已选板块的股票重合度上限 |

**调参顺序建议**：先看 `hits` 有多少条（25~40 合理），再看 `watchlist`（8~20 合理），最后看 `picks`（3 个）。多了收紧 `MIN_SHARE`，少了放宽 `MIN_W_EFF`。

> `GATE_STRONG` / `GATE_WATCH` 是**初值，需要校准**。跑两周后用真实的 score 分布决定：
> 如果每天都有一半板块过 70，就把门槛提到 75~80；如果一个都不达标，说明维度权重需要重新分配。
> 分数的首要作用是**当日排序**，绝对门槛的意义没那么大。

## 本地测试

改完代码先本地跑一遍，别直接粘进扣子。

```bash
python3 tests/test_nodes.py
```

会验证：

- 三个节点能正常执行
- 噪声标签全部拦截、真板块全部保留
- E3 的日期去重、连击判定、归并逻辑
- 空数据不崩

> `tests/sample_records.json` 是用真实 Top20 标签构造的 3 日样本，含一条重复日期，用来验证去重。

## 已知限制

1. **连续判断无法回溯**。成交额 Top20 是当日快照，昨天的排行榜没有免费接口能拿到。系统必须跑满 3 个交易日才有意义。
2. **板块资金流用「上榜个股之和」近似**。东财板块接口在部分网络环境被拦截，腾讯板块接口的板块名与东财对不上（`CPO概念` vs `共封装光模块(CPO）`），无法 join。
3. **广度标签会占前排**。`5G概念`、`人工智能` 这类覆盖 10 只以上票的标签更像「半个市场」，看的时候要往后翻一层找窄口径板块。
4. **数据源是公开网页接口**，随时可能变更或限流，仅供个人研究。
